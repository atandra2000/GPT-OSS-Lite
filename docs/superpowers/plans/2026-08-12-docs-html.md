# GPT-OSS-Lite Static Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a self-contained static HTML mirror of every GPT-OSS-Lite documentation page.

**Architecture:** Adapt the sibling projects' dependency-free Markdown-to-HTML renderer with a GPT-OSS document manifest and portal copy. Copy the renderer's single stylesheet as the generated local asset; the generator itself is the reproducible build source.

**Tech Stack:** Python standard library, static HTML/CSS, optional browser-hosted KaTeX and Highlight.js.

## Global Constraints

- Ship all Markdown pages listed in the GPT-OSS manifest as local `.html` twins.
- Require no Node.js package, framework, server, or new dependency.
- Retain only one generated local asset: `docs_html/assets/style.css`.
- Validate source docs with `python3 scripts/check_docs.py --check-symbols`.

---

### Task 1: Add the reproducible documentation renderer

**Files:**
- Create: `scripts/build_docs_html.py`
- Create: `assets/style.css`

**Interfaces:**
- Consumes: the explicit `DOC_FILES` manifest of source Markdown paths.
- Produces: `docs_html/index.html`, one `.html` twin per manifest entry, and `docs_html/assets/style.css` when invoked as `python3 scripts/build_docs_html.py`.

- [x] **Step 3: Run the generator**

Run: `python3 scripts/build_docs_html.py`

Expected: exit 0 and one “Generating” line for each source Markdown document.
